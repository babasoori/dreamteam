dreamteam starts or reuses Coach in a named Rex tab and returns to the shell. Coach dispatches requested assignments through Dreamteam tools. The first player opens to the right; later players open below the lowest existing player. Dispatch leaves focus unchanged.

Rex supplies the sidebar, tab list, activity indicators, pane focus, resizing, zoom, and live terminal input. No custom dashboard, roster widget, preview, or embedded terminal remains.

What Dreamteam owns

  • Roster roles, project scope, and one saved play.
  • Assignments, request-ID deduplication, explicit progress reports, and evidence reads.
  • A small CLI that launches and selects native Rex panes and stops only verified managed processes.

Codex owns the conversations, tools, sandbox, and approval dialogs. The human directs the team and accepts the work.

Working with the team

Talk directly to Coach. Use Rex to select a player’s pane. For shell access, dreamteam start penny adds or reuses Penny; dreamteam open coach returns focus to Coach. dreamteam status prints the workflow state. dreamteam stop team stops Coach first, then the managed players.

Ask Coach to define a play, or use dreamteam play before launch. dreamteam brief prints the optional planning brief. Saving a play or printing a brief never dispatches work.

Layout rules

All creation uses exact server, session, tab, and anchor identities. Repeated starts reuse a live pane. New players split the current bottom of the right column; closing a player lets Rex collapse its split naturally. Users can resize or zoom using Rex. Rearranged or unmanaged panes are not automatically overwritten.

Old separate-tab runtimes require explicit shutdown before starting the new layout. Existing conversations are not silently moved or restarted.

Lifecycle and evidence

Launch intent is saved before creating a pane. Lost responses are reconciled, never blindly retried. Input requires a verified idle Codex process and bracketed-paste support. Rex’s acknowledgment means bytes were queued, not that the assignment was consumed or completed. Reports still require review and human acceptance.

Closing the launcher leaves agents running. Explicit cleanup preserves the Rex server, session, current terminal, and unrelated tabs. Changed server or process identities block automatic actions.

Kept small

Standard-library Python and the installed Rex CLI. No terminal rendering, Textual, model SDK, background supervisor, or backend framework. The roster, saved play, and assignment formats are unchanged. Confirmed passes, acceptance controls, multiple saved plays, and automatic restart recovery remain future work.

Verified boundary

105 offline tests cover the launcher, split placement, lifecycle, plays, and coordination tools. A real Rex fixture check verified the exact three-pane layout, focus preservation, reuse, input, capture, and cleanup. A real Codex Coach/player roundtrip remains unverified.
